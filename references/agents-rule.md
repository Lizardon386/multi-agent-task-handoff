## 任务三档规范（必读必写，强制）

每个任务子目录**必须同时具备三份 Markdown**，缺一不可：

| 文件 | 读者 | 回答的问题 | 变化频率 |
|---|---|---|---|
| `README.md` | **用户 / 使用者** | 这是什么、能干什么、怎么跑起来、有什么限制 | 稳定，只在用法变化时改 |
| `DESIGN.md` | **方案评审者 / 二次开发的人** | **为什么这么设计**、架构与关键接缝、哪些语义已定死 | 稳定，只在设计变化时改 |
| `CONTEXT.md` | **agent / 协作者** | 做到哪一步了、下一步做什么、有什么坑 | **每次会话都要改** |

README 与 DESIGN 拆开是 2026-10-14 定的：取舍三列表留在说明书里会把使用步骤顶到第二屏，而任务推上 GitHub 后读者第一眼要的是"我怎么用"。归档判据一句话：**这条结论半年后还成立吗？** 成立进 DESIGN，不成立（进度、实测、踩坑）进 CONTEXT。

### 命名

**固定名不许变体、不许翻译**：`README.md`、`DESIGN.md`、`CONTEXT.md`、`AGENTS.md`（`DESIGN.md` 与另两份一样是约定基建，不是交付物，`[名]` 对它豁免）。第五个 `SKILL.md` 是 skill 加载器强制的文件名，只出现在 skill 仓库的工作树里，普通任务目录不该有它——闸门同样对它豁免 `[名]` 与「反引号裸名」，因为规范原文必然反复点名 `README.md`/`DESIGN.md`/`CONTEXT.md`。

**禁的是"角色重复"，不是"多一个文件"**：职责是「给人看的使用说明」的文件必须并回 `README.md`，职责是「为什么这么设计 / 架构 / 定死的语义」的必须并回 `DESIGN.md`，职责是「给 agent 看的交接/进度」的必须并回 `CONTEXT.md`——禁止 `使用说明.md` / `设计说明.md` / `部署说明.md` / `进度.md` / `notes.txt` 这类复制品。判断口诀：*"这是给谁看的说明，还是我干的活本身？"*

**其他输出文档（真正的交付物：设计稿、评审意见书、决策件、评估报告、问题清单）必须用中文命名**，如 `设计总览.md`、`归属决策件.md`。读者是中文同事、文件要转发进群聊和飞书，英文名对方得先猜。

豁免：非 `.md` 交付物（`.docx` / `.pdf` 须与供应商原件同名，改了版本对不上）、`_` 前缀的机器产物、`archive/` 与 `inputs/` 子目录内的文件、脚本与代码。

`check-docs.sh` 的 `[名]` 只扫任务目录**顶层的 `.md`**，文件名纯 ASCII 即判失败。

### README.md 必备章节（顺序固定）

```
# <任务目录名> · 使用说明
> 面向使用者：……。方案设计见同目录 DESIGN.md，任务进度与 agent 交接记录见 CONTEXT.md。
> 最近更新：YYYY-MM-DD
## 一句话说明
## 快速开始            ← 最短能跑通的命令序列
## 使用说明            ← 完整流程、可覆盖参数、日常操作表
## 产物与目录          ← 文件清单（交付物 / 本机工具 / 传入内网的部分）
## 限制与注意事项      ← 用户视角的边界与误操作风险
```

### DESIGN.md 必备章节（顺序固定）

```
# <任务目录名> · 方案设计
> 面向方案评审者与二次开发的人：为什么这么设计、设计成什么样、哪些语义已经定死。
> 最近更新：YYYY-MM-DD
## 问题与目标          ← 要解决什么、硬约束、成功判据
## 设计思路            ← 必须有「决策 / 理由 / 代价」三列表
## 架构与关键接缝      ← 模块划分、数据流、对外契约；有图用图，不用文字流程图
## 已定语义与边界      ← 定了就不再改的规则与约定、明确「不做什么」
```

### CONTEXT.md 必备章节（顺序固定）

```
# <任务目录名> · 会话上下文与进展
> 本文件是任务交接档案，供 agent 实时跟进。改动产物后请更新「当前状态」「变更记录」。
> 最近更新：YYYY-MM-DD（<来源>）
## 背景与目标
## 当前状态
## 计划 / 待办        ← 用 - [ ] 复选框，已完成打勾不删
## 关键约束与注意事项  ← 不可逆操作、就地修改风险、幂等性、外部硬约束
## 变更记录            ← - YYYY-MM-DD <来源agent>：<摘要>
## 给下一个 agent 的追加区
```

额外小节允许，各档既定节**不许删**。

**DESIGN 档可以省**：目录里已经有承担「方案设计」职责的交付文档（`架构设计.md`、`XX实施方案.md` 这类**复合名**，不是"名字里带'设计'"就算——评审意见书不算）时，不再单立 `DESIGN.md`，同一件事维持两份真源必然失同步。闸门输出 `[档] 方案设计已由交付文档「X.md」承担`（不计失败）并按该交付文档自己的规范放行；`DESIGN.md` 与替代文档都缺才报 `[缺]`。

### 分工红线

- 进度、验证记录、待办、遗留问题**只写在 `CONTEXT.md`**。
- 设计取舍、架构、已定语义**只写在 `DESIGN.md`**；操作步骤**只写在 `README.md`**。
- 多档共用的关键事实（端口、路径、硬性磁盘要求）： owning 那档写全文，其余档只留一行引用，不重述，否则必然失同步。
- 代码/脚本能自解释的不抄进文档；文档写**为什么**和**坑**。
- `设计思路` 三列表（在 DESIGN.md）每个决策都要写代价；只有结论没有代价的表等于没写。
- 改 DESIGN 的「已定语义与边界」必须在 CONTEXT 的「变更记录」留一行，说明为什么改。

### 产物链接（强制）

任何向用户呈现的文件产物都必须写成**可点击的 Markdown 链接**，不接受裸文件名 / 反引号路径 / 纯文本 `D:\...`。**按"链接出现在哪个面"分两套**——这两个面解析 `href` 的逻辑相反，用错面就点不开：

**场景一 · 文档内链接**（写进 `.md` 的：README 的「产物与目录」、CONTEXT 的「当前状态」与「变更记录」、交付物正文里的产物引用）——一律写**相对该文档自身目录**的路径；行号与文档内锚点写进链接**文字**，不用 `#L42`。

- 目标在文档下方：`[DspControlCore.h:88](coding/dspcontrol-hal/core/DspControlCore.h)`
- 目标在上方或兄弟任务：`[AGENTS.md](../AGENTS.md)`
- 会推 GitHub / 发给别人的 README **同样用相对路径**——GitHub 也解析相对链接，一份写法两种读者通吃；`file:///D:/...` 在别人机器上更是死链。
- **文档里不要写 `file:///`**：预览面板把 `href` 按"相对文档所在目录"解析，`file://` scheme 不在它的绝对地址白名单里——VSCode 预览报「文件不存在」（文件其实在），Qoder 文档预览干脆不渲染成链接。

```markdown
[DspControlCore.h](coding/dspcontrol-hal/core/DspControlCore.h)
[DspControlCore.h:88](coding/dspcontrol-hal/core/DspControlCore.h)
[AGENTS.md](../AGENTS.md)
[game.js](packages/client/src/game.js)
```

- 路径一律正斜杠；相对路径以**当前这份 .md 自己所在目录**为基准，不是工作区根。
- 闸门 `[链]` **两种形式都接受、也都验可达**（2026-10-14），所以满篇 `file:///` 的文档**不会报错**——它只是点不开。这条得靠写的人守，别指望闸门拦。
- 指向文档内位置（§ 节号、表内行号如 C4）时，锚点同样写进链接文字：`[归属决策件.md · C4行](信息收集/过时信息归档文档/归属决策件.md)`；锚点留在链接外（链接后跟裸的 `C4 行`）视同违规——链接文字必须自己说清点进去看哪。
- 自检会对「产物与目录」里**没有任何可点击链接**的 README 报 `[链]` 并**判失败**（2026-10-10 由告警升级：告警曾被 `| tail -2` 截掉，等于没有）。
- 反例（都点不开）：`` `game.js` ``、裸写 `D:\...\game.js`、文档里写 `file:///D:/...`、把方括号转义成 `\[文字\](目标)`（渲染成字面文本）、链接文字以 `\` 结尾（`\]` 会被当转义，整条链接解析失败）。

**场景二 · 聊天回复**——按宿主能力二选一（这是聊天面，与上面写进文档的规矩互不适用）：

- 宿主支持「工作区根相对路径 + `#L` 行锚点」点击跳行（Claude Code 的 VSCode 扩展已验证）：`[spidevice.c:489](dsp-hal-eval/finalfile/codecs/ccd5001/spidevice.c#L489)`，行范围 `#L217-L240`，点开直接跳到该行——这种宿主里指代码位置的首选。
- 其他宿主（Qoder 聊天侧边栏、Codex 等）或不确定时：用 `file:///` 绝对链接（**只有聊天侧边栏认它**），行号与文档内锚点写进链接文字。

依据（2026-10-14 纠正）：旧口径"本机文档首选 `file:///`"来自 2026-10-09 一次**只测了聊天侧边栏**的实测，被外推到了文档面。用户在 markdown 预览面板复测后结论相反：`file:///` 在 VSCode 预览报文件不存在、在 Qoder 文档预览不渲染成链接，改相对路径后两个面都能跳。两个渲染面解析逻辑不同，不能从一个外推到另一个；`dsp-hal-eval` 已按新口径把 175 条链接改成相对。另：`file:///` 本来也带不了行号（点开落在文件顶部），这是聊天面在支持跳行的宿主改用 `#L` 的独立理由。

### 会话节奏（每个 agent 都执行）

1. **进目录先读**：`CONTEXT.md` → `README.md` → `DESIGN.md`，再动文件。不要凭目录列表猜意图。
2. **开新任务即建档**：`bash multi-agent-task-handoff/scripts/init-task.sh <任务名>` 铺**三档**骨架，不许"会话结束再补"。
3. **收工必更新**：改了产物 → README 的「产物与目录」；设计变了 → DESIGN 相应节；有新结论/改动/踩坑 → 更新 CONTEXT 并在「变更记录」留一行。
4. **三档同步日期**：三档顶部「最近更新」与实际改动同日，且**三档彼此必须一致**——任何一档改了别的没跟上，就说明有一档在说谎。日期必须写在紧跟 H1 的 blockquote 行上（`> 最近更新：YYYY-MM-DD`），`[新]`/`[旧]`/`[期]` 只认这一行；正文里再写「最近更新：某日期」不算数，也不会被误当成顶部日期。
5. **自查闸门（强制）**：`bash multi-agent-task-handoff/scripts/check-docs.sh` 退出码 0 才算本次会话收尾完成。`STALE_DAYS=7 bash multi-agent-task-handoff/scripts/check-docs.sh` 可收紧过期告警（默认 30 天，只告警不失败）。
   检查项前缀与严重度：

   | 前缀 | 含义 | 后果 |
   |---|---|---|
   | `[缺]` | 三档文件不存在（DESIGN 可由「架构设计.md」这类方案设计类交付文档承担，见上） | 失败 |
   | `[构]` | 缺必备章节 | 失败 |
   | `[占]` | 留着模板占位符 / 日期没填 | 失败 |
   | `[题]` | H1 标题不含任务目录名（中文别名写成 `# 目录名（别名）· 使用说明` 就过，纯别名不过） | **失败**（2026-10-14 新增） |
   | `[空]` | 骨架未填（三档任一表格留全空行、CONTEXT 空待办；DESIGN「设计思路」三列表**任一格留空**也算） | 失败 |
   | `[链]` | 「产物与目录」没有任何可点击链接（`file:///` 或相对链接都算），**或**链接指向的文件不存在（两种形式都验；```` ``` ```` 围栏与行内 `` `code` `` 里的内容不验，避免代码示例里的 `[this](x)` 被当成链接——反引号按等长 run 配对，``[`x.md`](url)`` 先解开再验所以合法链接不漏；格式例子要写成代码段（**两个**反引号包住，单反引号包不住含反引号的例子），散文里裸写的链接形状 `[文字](链接)` 就是一条点不开的死链、照报——2026-10-14 曾给"占位符"开过豁免，结果当场打穿了证明 span 生效的那条反向对照（夹具 c8），已撤销），**或**顶层交付 `.md` 里用反引号裸写本任务文件名 / 引用已不存在的 `archive/`、`inputs/` 路径（不可点，等同死链） | **失败** |
   | `[名]` | 顶层输出 `.md` 用了纯 ASCII（英文）文件名（`README` / `DESIGN` / `CONTEXT` / `AGENTS` 四个固定名 + `SKILL.md` 豁免） | **失败** |
   | `[期]` | 三档「最近更新」日期不一致 | **失败** |
   | `[新]` | 顶部缺「最近更新：YYYY-MM-DD」 | 失败 |
   | `[旧]` | 超过 STALE_DAYS 未更新 | 仅告警（已归档任务本就该停在最后一天） |
   | `[档]` | 方案设计已由某交付文档承担，故不要求 `DESIGN.md` | **仅信息**，不影响退出码 |

   跑闸门**不要加管道**（`| tail`、`| grep`）——只看结尾两行会把前面的违规行截掉，制造假绿灯。

### 真源与「更新即铺满」（铁律）

本规范的**唯一真源是 skill 仓库的 git 工作树**——本机是 `D:\agent_workspace\multi-agent-task-handoff\`（布局：`SKILL.md` + `scripts/` + `assets/` + `references/`；仓库落地页就是根 `README.md`，2026-10-14 起不再有 `.github/README.md` 那份重复）。各 agent 的技能目录（`~\.qoder-cn\skills\`、`~\.codex\skills\`、`~\.claude\skills\`）与其它工作区的脚本副本目录（新名 `multi-agent-task-handoff/`，旧名 `tools/`）**都是下游副本**，改了会在下次铺满时被覆盖。

- 改完真源：先 `git commit` + `git push`（真源即发布源），再**立刻铺满本机**，否则其他 agent 下次会话仍在跑旧规矩，等于规矩分叉：

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File D:\agent_workspace\multi-agent-task-handoff\scripts\install-everywhere.ps1
  ```

  `-Source` 缺省 = 脚本所在 `scripts\` 的上一级 = 真源工作树，所以**必须从工作树里那份启动**（从下游扁平副本启动会把整个工作区当成 skill 源）。同一趟会幂等刷新：各 agent 的技能目录、各 agent 的全局规则块、每个已登记工作区的脚本副本（含 `install-everywhere.ps1` 自己，2026-10-12 起——之前它不铺自己，导致工作区那份长期停在旧版）；**副本目录就是真源本身时跳过**，免得往工作树上铺出第二份扁平脚本。**默认只补不删**：仓库里删掉的文件在各副本里会留着（幽灵副本带着旧规矩，而铺满输出照样全绿），需要清理时加 `-Prune`——先把待删清单打进输出、再删；`-Prune -DryRun` 只列不删。作用域仅限本脚本自己铺的两个子树（技能目录下的 skill 子树、工作区脚本副本目录），不碰任务目录与 `AGENTS.md`；反过来说，**工作区那个脚本副本目录归安装器所有，别往里放自己的笔记**。**真源工作树（本机 `D:\agent_workspace\multi-agent-task-handoff\`）的 `post-merge` 钩子已默认带 `-Prune`**（2026-10-15）：pull 那一趟无人值守，顺手把残留一起清掉，待删清单先打进输出再删；手动那一趟仍保持"只补不删"的保守默认。钩子配方写在仓库根 README 的「更新即铺满」一节——`.git/hooks/` 不被 git 跟踪，换机器照那段自建，文件必须 LF。
- 只铺单个工作区时用 `bash scripts/bootstrap.sh --root <工作区根>`（`--force` 覆盖脚本副本）。
- **改闸门判定必须先跑夹具**：`bash scripts/selftest.sh`（47 条断言，在隔离临时根上跑，不碰真实目录）+ `bash scripts/muttest.sh`（18 个变异，证明断言真会红），再与一份基线输出逐字节比对。闸门慢或错，收工就没人跑。

- **已有规则块的工作区不会被自动更新**：bootstrap 与 install-everywhere 都靠规则块标题判重（2026-10-14 起是正则 `任务[双三]档规范`，兼容拆分前的旧标题），只补不覆盖。skill 改了条款，必须**手工同步一次该工作区的 `AGENTS.md` 和各 agent 的全局规则块**（`.codex\AGENTS.md`、`.claude\CLAUDE.md`），否则那里的 agent 读到的还是旧版。

### 边界与特例
