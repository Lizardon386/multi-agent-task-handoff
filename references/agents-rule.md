## 任务双档规范（必读必写，强制）

每个任务子目录**必须同时具备两份 Markdown**，缺一不可：

| 文件 | 读者 | 回答的问题 | 变化频率 |
|---|---|---|---|
| `README.md` | **用户 / 使用者** | 这是什么、**为什么这么设计**、怎么用 | 稳定，只在设计或用法变化时改 |
| `CONTEXT.md` | **agent / 协作者** | 做到哪一步了、下一步做什么、有什么坑 | **每次会话都要改** |

### 命名

**固定名不许变体、不许翻译**：`README.md`、`CONTEXT.md`、`AGENTS.md`。

**禁的是"角色重复"，不是"多一个文件"**：职责是「给人看的说明」的文件必须并回 `README.md`，职责是「给 agent 看的交接/进度」的必须并回 `CONTEXT.md`——禁止 `使用说明.md` / `部署说明.md` / `进度.md` / `notes.txt` 这类双档复制品。判断口诀：*"这是给谁看的说明，还是我干的活本身？"*

**其他输出文档（真正的交付物：设计稿、评审意见书、决策件、评估报告、问题清单）必须用中文命名**，如 `设计总览.md`、`归属决策件.md`。读者是中文同事、文件要转发进群聊和飞书，英文名对方得先猜。

豁免：非 `.md` 交付物（`.docx` / `.pdf` 须与供应商原件同名，改了版本对不上）、`_` 前缀的机器产物、`archive/` 与 `inputs/` 子目录内的文件、脚本与代码。

`check-docs.sh` 的 `[名]` 只扫任务目录**顶层的 `.md`**，文件名纯 ASCII 即判失败。

### README.md 必备章节（顺序固定）

```
# <任务目录名> · 设计思路与使用说明
> 面向使用者：……。任务进度与 agent 交接记录见同目录 CONTEXT.md。
> 最近更新：YYYY-MM-DD
## 一句话说明
## 设计思路            ← 必须有「决策 / 理由 / 代价」三列表
## 快速开始            ← 最短能跑通的命令序列
## 使用说明            ← 完整流程、可覆盖参数、日常操作表
## 产物与目录          ← 文件清单（交付物 / 本机工具 / 传入内网的部分）
## 限制与注意事项      ← 用户视角的边界与误操作风险
```

### CONTEXT.md 必备章节（顺序固定）

```
# <任务目录名> · 会话上下文与进展
> 本文件是任务交接档案，供 agent 实时跟进。改动产物后请更新「当前状态」「变更记录」。
> 最近更新：YYYY-MM-DD（<来源>）
## 背景与目标
## 当前状态
## 计划 / 待办        ← 用 - [ ] 复选框，已完成打勾不删
## 关键约束与注意事项  ← 不可逆操作、就地修改风险、幂等性、外部硬约束
## 变更记录            ← - YYYY-MM-DD <来源agent>：<摘要>
## 给下一个 agent 的追加区
```

额外小节允许，既定六节**不许删**。

### 分工红线

- 进度、验证记录、待办、遗留问题**只写在 `CONTEXT.md`**。
- 设计取舍与操作步骤**只写在 `README.md`**；CONTEXT 里只写"入口文档是 README.md"。
- 两边都需要的关键事实（端口、路径、硬性磁盘要求）：CONTEXT 里一行引用，不重述，否则必然失同步。
- 代码/脚本能自解释的不抄进文档；文档写**为什么**和**坑**。
- `设计思路` 三列表每个决策都要写代价；只有结论没有代价的表等于没写。

### 产物链接（强制）

任何向用户呈现的文件产物都必须写成**可点击的 Markdown 链接**，不接受裸文件名 / 反引号路径 / 纯文本 `D:\...`。格式按链接所在位置分两套：

**场景一 · 工作区内的 `.md` 文档**（README 的「产物与目录」、CONTEXT 的「当前状态」与「变更记录」、交付物正文里的产物引用）——写成可点击链接，行号写在链接**文字**里，不用 `#L42` 锚点。形式按这份文档会不会离开本机分两种：

- 只在本机看（默认）：`file:///D:/...` 绝对链接。
- 要推到 GitHub / 发给别人的仓库 README：**仓库相对链接** `[game.js](packages/client/src/game.js)`——`file:///D:/...` 在别人机器上是死链。

```markdown
[game.js](file:///D:/agent_workspace/uno-webgame/game.js)
[game.js:42](file:///D:/agent_workspace/uno-webgame/game.js)
[game.js](packages/client/src/game.js)
```

- 协议固定 `file:///`（三斜杠），路径一律正斜杠；`D:\x\y.js` → `file:///D:/x/y.js`。
- 本机文档仍首选 `file:///`（它在任意查看器里点得开）；`[链]` 从 2026-10-14 起**两种形式都接受、也都验可达**。
- 指向文档内位置（§ 节号、表内行号如 C4）时，锚点与行号同样处理，写进链接文字：`[归属决策件.md · C4行](file:///D:/agent_workspace/dsp-hal-eval/归属决策件.md)`；锚点留在链接外（链接后跟裸的 `C4 行`）视同违规——链接文字必须自己说清点进去看哪。
- 自检会对「产物与目录」里**没有任何可点击链接**的 README 报 `[链]` 并**判失败**（2026-10-10 由告警升级：告警曾被 `| tail -2` 截掉，等于没有）。
- 反例（点不开）：`` `game.js` ``、裸写 `D:\...\game.js`。

**场景二 · 聊天回复**——按宿主能力二选一：

- 宿主支持「工作区根相对路径 + `#L` 行锚点」点击跳行（Claude Code 的 VSCode 扩展已验证）：`[spidevice.c:489](dsp-hal-eval/finalfile/codecs/ccd5001/spidevice.c#L489)`，行范围 `#L217-L240`，点开直接跳到该行——这种宿主里指代码位置的首选。
- 其他宿主（Qoder 侧边栏、Codex 等）或不确定时：沿用场景一的 `file:///`，行号与文档内锚点都写进链接文字。

依据（2026-10-10 实测拍板）：`file:///` 链接只负责打开文件、带不了行号——用户点击后文件开在顶部，得再 `Ctrl+G` 手动跳行。聊天场景在支持跳行的宿主里改用锚点格式；文档场景默认 `file:///`，2026-10-14 起闸门同时接受仓库相对链接。

### 会话节奏（每个 agent 都执行）

1. **进目录先读**：`CONTEXT.md` → `README.md`，再动文件。不要凭目录列表猜意图。
2. **开新任务即建档**：`bash tools/init-task.sh <任务名>` 铺骨架，不许"会话结束再补"。
3. **收工必更新**：改了产物 → 更新 README 对应章节；有新结论/改动/踩坑 → 更新 CONTEXT 并在「变更记录」留一行。
4. **两侧同步日期**：两档顶部「最近更新」与实际改动同日，且**两档彼此必须一致**——一边改了另一边没跟上，就说明有一侧在说谎。日期必须写在紧跟 H1 的 blockquote 行上（`> 最近更新：YYYY-MM-DD`），`[新]`/`[旧]`/`[期]` 只认这一行；正文里再写「最近更新：某日期」不算数，也不会被误当成顶部日期。
5. **自查闸门（强制）**：`bash tools/check-docs.sh` 退出码 0 才算本次会话收尾完成。`STALE_DAYS=7 bash tools/check-docs.sh` 可收紧过期告警（默认 30 天，只告警不失败）。
   检查项前缀与严重度：

   | 前缀 | 含义 | 后果 |
   |---|---|---|
   | `[缺]` | 双档文件不存在 | 失败 |
   | `[构]` | 缺必备章节 | 失败 |
   | `[占]` | 留着模板占位符 / 日期没填 | 失败 |
   | `[空]` | 骨架未填（空取舍表、空待办） | 失败 |
   | `[链]` | 「产物与目录」没有任何可点击链接（`file:///` 或相对链接都算），**或**链接指向的文件不存在（两种形式都验；```` ``` ```` 围栏内的内容不验，避免代码示例里的 `[this](x)` 被当成链接），**或**顶层交付 `.md` 里用反引号裸写本任务文件名 / 引用已不存在的 `archive/`、`inputs/` 路径（不可点，等同死链） | **失败** |
   | `[名]` | 顶层输出 `.md` 用了纯 ASCII（英文）文件名 | **失败** |
   | `[期]` | 两档「最近更新」日期不一致 | **失败** |
   | `[新]` | 顶部缺「最近更新：YYYY-MM-DD」 | 失败 |
   | `[旧]` | 超过 STALE_DAYS 未更新 | 仅告警（已归档任务本就该停在最后一天） |

   跑闸门**不要加管道**（`| tail`、`| grep`）——只看结尾两行会把前面的违规行截掉，制造假绿灯。

### 真源与「更新即铺满」（铁律）

本规范的**唯一真源是用户级 skill `multi-agent-task-handoff`**；工作区 `tools/` 里的脚本只是同步副本。

- skill 任何变更——不管是本地改的还是 `git pull` 拉进来的——**必须立刻铺满本机**，否则其他 agent 下次会话仍在跑旧规矩，等于规矩分叉：

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File <最新skill目录>\scripts\install-everywhere.ps1
  ```

  `-Source` 缺省 = **脚本自身所在的 skill 目录**，所以永远从最新那份里运行它。同一趟会幂等刷新：各 agent 的技能目录、各 agent 的全局规则块、每个已登记工作区的 `tools/` 副本（含 `install-everywhere.ps1` 自己，2026-10-12 起——之前它不铺自己，导致工作区那份长期停在旧版）。
- 只铺单个工作区时用 `bash tools/bootstrap.sh --root <工作区根>`（`--force` 覆盖脚本副本）。
- **不要只在本工作区副本里修 bug**：下次铺满会被覆盖，改动一律提到 skill。
- **已有规则块的工作区不会被自动更新**：bootstrap 与 install-everywhere 都靠「任务双档规范」标题判重，只补不覆盖。skill 改了条款，必须**手工同步一次该工作区的 `AGENTS.md`**，否则那里的 agent 读到的还是旧版。

### 边界与特例

- `tools/`、`templates/`、`node_modules/`、`.git/` 是基础设施与素材，不参与自检。
- 一次性/纯搬运目录也要双档：README 可短，但取舍表必须写清为什么这么做，CONTEXT 的「变更记录」必须有最后一行状态。
- 引入外部 git 仓库源码的任务，双档照样要写，源码自身规范另计。
- 跨任务共用信息写在本目录 CONTEXT.md 的「关键约束」并引用另一任务的文档名，不复制粘贴。
