multi-agent-task-handoff — 多 agent 任务交接

用法:
  multi-agent-task-handoff [--workspace <PATH>] [--nosave] [--gear <key>[=<值>] | --gear list | --help | --resume | --suspend [--local | --commit | --push] | --post <message> [--new | --next <ID | 会话名>] | --doc [--guard | --init] [--target DIR] | --check | --fix | --probe [--static | --live] | --printpath [--host NAME | --target DIR]]

命令:
  --resume                  接盘 / 接手：读 handoff/PROMPT.md → handoff/CONTEXT.md，
                            冲突以 CONTEXT 为准；核锚点、跑验证
  --suspend [--local | --commit | --push]
                            压卡（按需）+ 收工 + 写 handoff/PROMPT.md
                              --local   只写卡与 PROMPT，不操作 git
                              --commit  提交协议管理文档（含 --doc 的移动/删除）
                              --push    提交并推送（隐含 commit；网络错误重试 3 次，间隔 3 秒；
                                        Windows 再加 HTTP/1.1 + OpenSSL 回退 3 次）
                            默认挡位读 config.toml 的 [defaults].suspend
  --post <message> [--new | --next <ID | 会话名>]
                            投递 / 热交接：把 message 投给另一个会话；不写卡、不动 git
                              --new     新建会话后投递（必须绑定当前项目目录，落 worktree 视为失败）
                              --next <ID | 会话名> 投递到已有会话；
                                        目标 stopped/completed 且不自动唤醒时先手动打开/继续，再投递
                            默认读 config.toml 的 [defaults].post（new / next）
  --doc [--guard | --init] [--target DIR]
                            默认挡位读 config.toml 的 [defaults].doc（guard）
                              --guard   维护已有文档：删 ## 文档 表的失效协议行；其余只报告/建议，不新增/不还原
                              --init    显式创建缺失文档：CONTEXT 必生成；README 仅 GitHub/确认；
                                        DESIGN 需取舍+确认；COMMANDS 仅用户要求
                            布局/标记/迁移链接由 --doc 本身处理；拿不准给选项
  --check                   自检 / 更新：只读检查，报告 ✅ / 🟡 / ⛔
  --fix                     修复：只修安装/配置等非文档整理项，不碰文档增删迁移
  --probe [--static | --live]  摸底 / 探测：按 assets/PROBE.md 固定清单实测并更新能力表
                              --static 只做零副作用检查
                              --live  先出计划、确认一次后跑完 S+L1+L2（每次 live 跑 L2）
                            默认挡位读 config.toml 的 [defaults].probe
  --printpath [--host NAME | --target DIR]
                            路径诊断：表格输出配置目录 / 配置文件 / 工作区根 / 能力表
                            （含更新日期）/ 安装注册表 / 源仓库 / 宿主 / 当前安装副本 /
                            全部副本的路径与 commit；--host / --target 显式指定；
                            注册表缺失且检测到旧 .skill-sync-paths 时只提示，不迁移
  --gear <key>[=<值>] | --gear list
                            读/写 config.toml 的 [defaults] 挡位
                            <key> 与 [defaults] 键同名；list 列出键、默认值与允许值
                            读取/写入需要 config.toml；list 不需要配置
                            省略值只读取；值不在白名单时不修改文件
  --workspace <PATH> [--nosave]
                            全局：指定工作区根；默认写回 config.toml；
                            --nosave 只本次生效，不写回
  --help                    显示本表

执行层:
  agent 协议命令（--resume / --suspend / --post / --check / --fix / --probe / --workspace）
  由 agent 按 SKILL 执行；脚本直接支持 --printpath / --doc / --syncall / --push / --save / --gear。
  普通项目的 --suspend --push 在项目目录运行安装副本的 --push（推当前目录仓库；源仓库环境推源仓库）。
  --probe 的固定清单见 skill 安装目录的 assets/PROBE.md。

规则:
  一次只用一个命令；不支持命令叠加
  --workspace 可与一个命令同用；--nosave 只跟 --workspace
  --local / --commit / --push 只能跟 --suspend
  --guard / --init 只能跟 --doc
  --new / --next 只能跟 --post；两者不能同时用；message 必填
  --live 只能跟 --probe
  --printpath 是独立命令；--host 只能跟 --printpath；--target 可跟 --printpath / --doc
  --gear 是独立命令；键与允许值由脚本映射决定，写入值非法时不修改
  --help 单独使用
  无参数等同 --resume

中文别名:
  接盘/接手、压卡/收工/交接、投递/热交接、工程化/工程/建档、自检/更新、修复、
  摸底/探测、路径诊断、帮助

样例:
  --workspace D:/agent_workspace --resume
  --workspace "C:/My Workspace" --resume
  --suspend --commit
  --post "接手 V4 文档布局，先读 handoff/PROMPT.md" --next <ID | 会话名>
  --post "接手 V4 文档布局" --new
  --fix
  --probe --live
  --doc
  --doc --init
  --gear list
  --gear suspend=push
  --printpath

路径诊断:
  优先用 --printpath（表格输出）；脚本 / CI 可跑 scripts/handoff.sh --printpath；安装用 install.sh
